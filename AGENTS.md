# scd: Agent Context

## Repository Shape
- One Go module, `github.com/a1ekseev/scd`, builds one binary, `scd`, which runs four services:
  - `scd`: Subscription Control Daemon. Manages Xray through the gRPC API and serves the status dashboard. Its commands are top level: `scd sync|daemon|generate|validate-config|print-config`.
  - `scd sfc`: Subscription Filter Control. Filters subscriptions and serves public base64 payloads: `scd sfc serve|refresh|validate-config|print-config`.
  - `scd gtl`: Gen Test Load. An HTTP random load payload generator: `scd gtl serve|validate-config|print-config`.
  - `scd wgp`: WireGuard provider. Keeps provider accounts and keys and publishes candidate files for scd: `scd wgp serve|login|logout|validate-config|print-config`.
- Layout:
  - `cmd/scd/`: entry point. `main.version` is set by ldflags.
  - `internal/cli/`: root cobra command and `--version` (root only). Mounts the four services.
  - `internal/common/`: shared code only. `buildinfo candidate cliutil configload cron cronloop httpserve inputsrc jsonout labelfilter listenaddr logging neterr regexlit schema securefile sigctx subscription vless wgpstatus`.
  - `internal/scd/`, `internal/sfc/`, `internal/gtl/`, `internal/wgp/`: the services (`config/`, `cli/`, …).
  - `internal/archtest/`: import-boundary test.
  - `internal/crosstest/`: `_test.go` only; the one place that may import scd and wgp together. Nothing imports it.
  - `testdata/reference/`: frozen reference outputs of the previous implementation, used by Go tests (D20).
  - `docker/`: example and real-shape configs, fixtures, test Xray config.
  - `scripts/`: CI checks and compose smoke.
- User docs: `README.md`.

## Common Rules
- Go `1.27` (`go 1.27.0`, `toolchain go1.27.3`). Use the latest dependency versions, except xray-core and uTLS.
- uTLS (`github.com/refraction-networking/utls`) is a direct dependency (wgp transport) at exactly the version the xray-core pin requires, never newer; it moves only with an xray-core bump. `scripts/check-xray-version.sh` checks it with `go mod graph` and `go list -m`.
- `internal/scd`, `internal/sfc`, `internal/gtl` and `internal/wgp` never import each other, and `internal/common` imports no service. `internal/archtest` enforces this. Shared code goes only in `internal/common`.
- xray-core is pinned by commit: `v1.260327.1-0.20261021115930-1b1647cd9ddf` = Xray v26.10.21. Never `@latest`. Update the go.mod pin, the compose image `ghcr.io/xtls/xray-core:<ver>` and `.xray-version` **together**; `scripts/check-xray-version.sh` checks this.
- Behaviour follows Go conventions (D9): Go error texts, `log/slog` to stderr, `regexp` (RE2), `net/url`, stdlib base64, `strings.Compare` ordering. Kept as a contract: log `event` names and fields, the status JSON API (additive only, `version: 1`), the dashboard look (visual regression), and Xray API behaviour (RPC set and order, fixed resources, rollback, error texts). The RPC order is remove → add for sync, repair, rejoin and candidate replacement: a tunnel never has two outbounds in Xray at once. Replacement: `RemoveRule(route-old)` → `RemoveOutbound(current)` → `RemoveOutbound(the other outbound tag)` → `RemoveInbound(in-old)` → `AddOutbound(new, prefixed)` → `AddInbound(in-new, same port)` → `AddRule(route-new → new)`; removal without replacement stops after `RemoveInbound`; filling an empty slot (`apply.AddTunnel`, only below `maxActive`): `AddOutbound` → `AddInbound` → `AddRule`, a failure removes what was added in reverse. Repair and the monitor's replacement start with a read-only `ListInbounds`; a missing inbound of the tunnel resets its source hashes and changes nothing in Xray. Xray API error texts are kept, except that `xrayapi.mapError` drops the local address of a network error inside a status message (`common/neterr.StableText`, `read tcp <local>-><xray>` → `read tcp <xray>`). Log policy: one event per decision or state change; per-step, per-kind and repeated events are `debug`; errors and warnings are edge-triggered with `*_recovered`; never log keys, tokens, URL paths or queries (also inside error texts), sfc output ids, Proton UID/serials, WARP device ids/tokens, endpoint IPs. A failure after the logger exists is `service_failed` (`cliutil.LogFailure`, `cliutil.ErrLogged`: not printed again).
- Lint: `golangci-lint` v2.15.0 with `.golangci.yml` (gofumpt and goimports formatters, revive). Every package and exported identifier needs a doc comment. Do not add `//nolint` without a reason.
- Tests use stdlib `testing`, table-driven where it fits, with real in-process servers (`httptest`, bufconn fake Xray `internal/scd/xrayapi/xrayfake`) instead of mocks.
- `**/config.yml` is ignored by git. Local `docker/<svc>/config.yml` files can hold the owner's real configs: never create, modify or assume them. Tracked configs are `docker/<svc>/config.example.yml`, `config.real-shape.yml` (old form) and `config.real-shape.go.yml` (Go form).
- Never commit real subscription URLs, hosts, UUIDs, keys, paths or sfc output ids. Use the sanitized fixtures in `docker/fixtures/` (`real-shapes/` included).
- The tree is Go-only (`scripts/check-no-node.sh`); the only `.js` file is the browser script `internal/scd/status/web/dashboard.js` of the dashboard.

## scd Notes
- A subscription is `{id, enabled, sources[], target}`; the old subscription keys and `target.inboundSocks.portRange` are unknown keys. A source `id` prefixes its tags (`id: vless` gives the old tags) and owns four namespaces on its target: `<obsPrefix><id>-`, `<id>-` (outbounds), `in-<id>-`, `route-<id>-` (`apply.Namespace`). `target.address` is unique, so a subscription is one Xray: within it source ids are unique and their `<id>-` prefixes and port ranges do not overlap. `normalize.Policy.TagPrefix` is required (empty panics).
- Pipeline:
  0. `syncer`, per enabled subscription: orphans first (`apply.RemoveOrphans`, under the target mutex): non-fixed resources outside every enabled source's namespace, rule → inbound → outbound, enabled kinds only; rules with an empty `ruleTag` are skipped (`RemoveRule("")` is never sent). An error stops that target for this sync (`orphan_remove_failed`).
  1. `syncer`: for each enabled source, in id order, load input (`common/inputsrc`: file, http(s) or stdin; `maxInputBytes`; `fetchUserAgent`; redacted `fetchHeaders`). A `wireguard` or `masque` source reads only an absolute path through `common/securefile.ReadPrivate` (`ErrRefused` → `reasonCode: wireguard_input_refused` / `masque_input_refused`).
  2. `common/subscription` + `common/vless`: split lines and parse.
  3. `normalize`: scope (D26), allowInsecure policy, flow, ML-KEM key checks, tags.
  4. `manifest`: build, then filter (country, then label); `outbound` builds the v26 JSON, and `conf.Build` validates it. `wireguard`: `common/candidate.ParseWireGuard` (`wireguard_invalid`, field named, never the value) → `outbound.BuildWireGuard` (always `noKernelTun: true`, `sockopt.domainStrategy`) → tag `<id>-<cc>-<city>-wg-<PublicHash>`; `masque`: `ParseMasque` (`masque_invalid`) → `outbound.BuildMasque` (always `security: tls` with `serverName`, `alpn: ["h2"]` only for `h2`, no `fingerprint`, headers or `pinnedPeerCertSha256`; key as std base64 SEC 1, peer key as PEM PKIX) → tag `<id>-<cc>-<city>-mq-<PublicHash>`; both through `manifest.BuildCandidates`; filters by `selection.Filter` (entry, exit, label).
  5. `topology`: tunnels of one source, `in-`/`route-` tags, sequential ports from the source `portRange`; lines beyond it are skipped (`port_range_exhausted`). `wireguard`/`masque`: `selection.Rank` + `Pick` give at most `maxActive` active candidates (no two with one key; a masque key is its device public key, its lines follow each other by `priority`), slot `i` = rank `i`.
  6. `resources`: SOCKS inbounds and routing rules.
  7. `apply`, per source: outbound → inbound → routing; remove own, add new; fixed and other sources' resources never touched; outbound-only rollback. One source failing does not touch the others.
  8. `state`: memory-only hashes and topology per source (`Target.Sources`), tunnels of all sources (source, then tag) with monitor state.
- Logs and sync reports: `subscriptionId` is the subscription, `sourceId` the source id. `sync_finished` (`durationMs`, `sourcesApplied/Unchanged/Failed`, `resourcesAdded/Replaced/Removed`, `skippedLines`, `appliedSourceIds` = `<subscriptionId>/<sourceId>` of the sources whose apply changed Xray, omitted when empty) closes every sync; `sync_started` and `apply_finished` are debug. `xray_state_drift` is warn once per target (`state.Target.StateLost`: marked sources by id, filled by the drift check and the monitor), debug for its other sources; a sync unmarks each source it loaded and applied whose mark is older than the sync (or came from its own drift check), `xray_state_restored` (`lostForMs`) when none is left; after a partial restore the next new mark is warn again. A marked source comes back only after its input loads: while its load fails, `xray_state_restore_blocked` (warn once per source and episode, then debug). `subscription_fetch_failed`, `apply_failed` (one line per source, not per kind; none for a fetch, orphan or validation failure, which have their own event) and `manifest_entry_warning` (`port_range_exhausted`: one line with `count`) are edge-triggered per source in `Syncer`, `orphan_remove_failed` per subscription (debug, as is `orphan_remove_recovered`, when the API is unavailable: `xray_unavailable`/`xray_recovered`; the recovery of a failure logged only at debug is debug); `subscription_fetch_recovered` and `orphan_remove_recovered` end them. Fetch errors drop the local address of a network error (`common/neterr.Stable`).
- `outbound.Spec` is a VLESS `Outbound`, a `WireGuard` or a `Masque`; its JSON (print, hash) shows secret keys as `<redacted>`, only `ToProto` sees them. A WireGuard or MASQUE key, preshared key and `rawBase64` of such an outbound never appear in logs, reports, `generate`, `print-config`, `/api/*` or HTML (guard tests). `manifest.Entry.Candidate` holds the key in memory only (`json:"-"`).
- Owner invariant: Xray never holds more than `maxActive` outbounds of a `wireguard` or `masque` source at any RPC (remove before add in apply, rollback, repair, rejoin, replacement); tests replay `xrayfake.Calls()` and check the fake after every RPC. It does not rely on state: every mutating client of sync and monitor is `apply.Capped`, which sends `ListOutbounds` before each `AddOutbound` of a source with `maxActive` and refuses it (`apply.ErrCapReached`, the source hashes are reset) when the source already has `maxActive` outbounds, both tags counted; `restoreBackups` uses the same `apply.CheckCap`. A failed full apply of such a source drops its tunnels from state.
- `wireguard` and `masque` sync (`syncer/wireguard.go`): a full apply when the source has no state, its hashes were reset, `apply.ConfigHash` changed or on drift (quarantined pairs excluded); otherwise `selection.Decide` (gone/changed/better with `switchMarginPercent` × `switchConfirmChecks`) → `apply.ReplaceTunnel`/`RemoveTunnel` per slot, then empty slots are filled by `apply.AddTunnel` (lowest free port, `reasonCode: vacant`). A failure (`apply.ErrReplaceFailed`) empties the slot and resets the source hashes. `monitor.ReplaceFailed` replaces a tunnel after `replaceAfterFailures` (`TunnelMonitor.FailuresInRow`, not reset by repair) and quarantines its pair (`PairKey{Key, Endpoint, Transport}`: a masque triple; `Decide` never switches a healthy tunnel to another transport of its key, and a full apply keeps the active transport of a key); without a candidate the tunnel stays in repair (`no_replacement` warning, `candidate_no_replacement` once). `source_recovered` ends a source's episode without a live tunnel (`state.Source.NoLiveSince`, started by a `candidate_no_replacement` (warn) while no other tunnel of the source is healthy; inside it `candidate_replaced` (`failed`), `candidate_no_replacement` and `tunnel_repaired` of the source are debug; ended by any good check of its tunnels). `monitor.ReplaceFailed` replaces nothing while the source's hashes are reset (it waits for a full apply; checked under the target lock); the tunnel is repaired instead. Events: `candidate_replaced`, `candidate_removed`, `candidate_replace_failed`, `candidate_no_replacement` (`fromTag`, `toTag`, `reasonCode` = `gone|changed|failed|better|vacant`; with `failed` also `probeError`, `failuresInRow`). `sources[].monitor` overrides `timeoutMs`/`retry` for any type. An empty candidate file (`TotalLines == 0`, `manifest.FromSource`) is valid, not a source failure: every tunnel is removed (`no_replacement`); a file whose lines are all rejected still fails validation.
- Provider names (`provider=` of a candidate) live only in the table of `common/candidate`; `internal/scd` never branches on them (`archtest`; the only allowed match is Xray's own name of the `masqueSettings` device block, `json:"warp"` / `GetWarp()`).
- `xrayapi` is the only package that talks gRPC to Xray; its errors are `*xrayapi.Error` with `Unavailable` set for gRPC Unavailable and DeadlineExceeded (`xrayapi.IsUnavailable`). Mutations: Handler List/Add/Remove Outbound/Inbound and Routing ListRule/AddRule/RemoveRule. Read-only: `GetBalancerInfo` and `GetOutboundStatus`.
- Sync, repair, rejoin and replacement share the per-target mutex in `state`. Monitors and balancer selection read without it.
- `daemon` runs `common/cronloop` loops: sync; per subscription the tunnel monitor, balancer monitor and balancer selection; per remote instance a status poll. It also runs the status HTTP server. On SIGINT/SIGTERM, loops stop at once, in-flight Xray mutations finish (`context.WithoutCancel`) but no new source is loaded and no new target or source is applied, then pending remote pings, then the HTTP server. There is no hot reload.
- `monitor`: tunnel probes through the generated SOCKS inbounds (`socks`). Repair recreates the outbound without the observatory prefix; rejoin restores it. Both remove first (rule, outbound), then add (outbound, rule); a failed `RemoveOutbound` stops either before any add and restores the old rule best effort (an unknown tag is no error in Xray); a failed rejoin add is rolled back best effort to the unprefixed outbound. `balancerMonitor` is observe-only, with an optional remote push. Both run only after a sync reached the target. `tunnel_repaired` carries `probeError` and `failuresInRow`; `tunnel_repair_failed` is edge-triggered (`TunnelMonitor.LastRepairError`); the first good check after degraded/repairing is one info line: `tunnel_rejoined_balancer` with `failedForMs` for a tunnel that goes back into the balancer, else `tunnel_recovered`; `balancer_degraded`/`balancer_recovered` on a change of the balancer check; `xray_unavailable`/`xray_recovered` (`state.Target.XrayDown`, `state.NoteXray`, `xrayapi.IsUnavailable`): one error per target and episode, cleared only by a successful API RPC of monitor, balancer selection or orphan removal (never by a probe), and meanwhile `tunnel_repair_failed`, `tunnel_rejoin_failed`, `candidate_replace_failed`, `balancer_selection_failed`/`_recovered` and `balancer_observatory_unavailable` (also when `GetBalancerInfo` failed in the same tick) are debug; `xray_state_lost` (monitor, inbound missing; `StateLost`, dedup only, cleared by sync as above); `tunnel_rejoin_failed` is edge-triggered (`TunnelMonitor.LastRejoinError`); `tunnel_flapping`/`tunnel_down`/`tunnel_stable` (a flap is a successful repair with `FailuresInRow == 1`; 3 in 60 min start an episode in which the tunnel's repaired/rejoined/recovered lines are debug; it ends after 60 min without a failed check or with 3 failed checks in a row; `TunnelMonitor.Flap`, not in the API; a full apply of the same tag carries it and `FailingSince`, unless the source is in `StateLost`); `tunnel_repaired` is warn once per failure series; `balancer_selection_changed` is info only for the first pick, a mode change or a move to or from no pick; `remote_status_*` show `apiUrl` and errors through `inputsrc.RedactURL`.
- `balancer`: read-only balancer selection view (D22). Never calls `OverrideBalancerTarget`.
- `status`: dashboard (`html/template` + `web/` assets, embedded), `/api/status`, `/api/instance-status`, `/api/instances`, `/api/runtime-state` (secrets redacted and `rawBase64` omitted unless `includeSecrets`; never for WireGuard or MASQUE; `expected` of a `wireguard`/`masque` source is its active set in `state`). `aggregate` holds the remote snapshots. Tunnel `protocol` and source `maxActive`/`activeCount`/`candidateCount` are written only for `wireguard` and `masque`. `wgp[]` (`/api/status`, `/api/instance-status`; `wgp.go`): one block per input directory of the enabled `wireguard`/`masque` sources that holds `status.json` (`common/wgpstatus`, 64 KiB, read on every request); a read or parse error is a block with `error` and no host path; no file, no key. The dashboard draws only the common fields, never switches on the provider type.
- `country`: flag emoji → ISO2. Labels are not interpreted beyond country and city (D33).

## sfc Notes
- No Xray. Per subscription: fetch (with fetchUserAgent and fetchHeaders) → parse with the shared `common/vless` (same parameter list as scd, no applicability checks) → per-output label filter (`common/labelfilter`) → keep raw lines in original order → base64.
- Outputs are served only from memory at `<pathRoute>/<output id>`; output ids are globally unique. `GET /healthz` is also served. Profile headers are sent only on a `userAgent` prefix match.
- Failure rules:
  - A failed download falls back to the disk source cache `<config dir>/.sfc-cache/<id>.subscription`.
  - With no cache, the previous payloads are kept.
  - An empty filtered output fails that output and keeps its previous payload.
  - No payload yet → `502`.
- `serve`: one initial refresh before listening, then `refreshSchedule`. Overruns are skipped. Fetch and output failures are logged once (edge-triggered) with `subscription_refresh_recovered` / `output_recovered`; `output_refresh_failed` and `output_recovered` are an empty output and its end (a load failure ends with `subscription_refresh_recovered` only); `server_stopping` on the signal.

## gtl Notes
- `GET /healthz`, `GET <load.path>/<sizeKb>` → always `200` for a valid size, `application/octet-stream`, `content-length = sizeKb*1024`, no custom headers. Bad size or a size above `maxSizeKb` → `400`; other paths → `404`; non-GET → `405`.
- Payload (`internal/gtl/payload`): AES-128-CTR keystream, streamed in 64 KiB chunks from one reused buffer. The key is random per process (memory only, never logged), the IV random per request, so no two bodies repeat and middleboxes see no fingerprintable content. Nothing decrypts it.
- `load.path` is required: starts with `/`, is not `/`, has no trailing `/`, query or hash. Unknown config keys are errors.

## wgp Notes
- Provider registry (`internal/wgp/provider`): a provider type is a package `internal/wgp/provider/<type>` that calls `provider.Register(<type>, provider.Factory{…})` from `init`; a repeated type panics. **A new provider = that package + one blank import line in `internal/wgp/provider/all`.** The core (config, cli, …) never names a type; `internal/archtest` checks that no core file names a provider, comments included.
- `Factory.New` parses the provider subtree (`n.Strict(provider.CommonKeys…, own keys…)`, unknown keys are errors) with `provider.Env` (id, output, identification, `deviceNamePrefix`, `keys`, `api`). `Factory.Identification` parses `identification.<type>`, required when a provider of the type is configured. `Factory.Candidates` makes `outputs[].candidates` required (≥ 1) or an error.
- `Provider{ID, Kind, Tick(ctx, Store) (Result, error)}`, `Result{Lines, Status wgpstatus.Provider, Warnings, Events}` (the core logs `Events` (before the cancellation check) with `providerId`/`providerType`/`outputId`/`slot`, which a provider cannot override; each warning as `provider_warning`; a nil error with `Status.State == error` publishes the lines and logs `provider_error`; warnings and errors are edge-triggered: a repeat is `debug`, the way back to ok is `provider_recovered`). Optional `Interactive{Login, Logout}` by type assertion; `login`/`logout` of another provider fail with `provider %q (type %q) does not support login`. `Store` is the encrypted state record of one provider.
- `print-config` prints the common provider keys, then the provider's JSON object; it must hold no secrets. `state.keyFile` is printed as a path only.
- Config rules: ids `[a-z0-9]+`, outputs ↔ providers 1:1 (an enabled provider needs an output), every output `path` absolute and in one directory, not `status.json`. IANA zones are checked with `provider.Timezone` against the embedded `time/tzdata`.
- `internal/wgp/store` implements `Store`: `Lock(dir)` (flock on `<dir>/wgp.lock` with the pid; released by the kernel on exit, so no stale lock; a held lock fails at once), then `Open(dir, keyFile)`: dir not a symlink, owner = process uid, no `0o077` bits; every entry a regular file with the same rules; key = base64 of 32 bytes via `securefile.ReadPrivate`; every `<id>.state` is opened. Record = `WGPSTAT1 | nonce(12) | AES-256-GCM(JSON)`, AAD `"wgp-state-v1|"+id`, `securefile.WriteAtomic`, ≤ 1 MiB; `Save` takes JSON only. A record that does not open is fatal (Open fails, so `serve`/`login`/`logout` do not start) and is never recreated. The key appears only as `KeySHA8()` (log `keySha8`, event `state_opened`); errors never hold the key or record contents.
- Test-only fake types live in `internal/wgp/provider/providertest` (`fakelogin` is Interactive); only tests import it.
- `serve`: lock and open the state, listen on `server.listen`, then `internal/wgp/daemon` runs one `common/cronloop` per enabled provider (first tick at start, an overlapping tick skipped) next to `internal/wgp/server` (`common/httpserve`). On SIGINT/SIGTERM the loops stop at once and wait for an active tick (its ctx is cancelled; a tick failing because of it records nothing), then the server drains; the lock goes last. `server_stopping` is logged on the signal.
- A tick: `Tick` → `output.Publish(out, lines)` → `wgpstatus.Write` of all providers that ticked (config order). `Publish` keeps the provider's order (bytes depend only on the lines), rejects an empty list (only `PublishEmpty` writes an empty file: the daemon calls it for a tick with no lines and no error, "no live candidate"; a tick error keeps the file) and any line that fails `candidate.Parse*` of the provider `Kind` (the file stays), skips the write when the bytes are equal (mtime kept), writes through `securefile.WriteAtomic`, and returns an `output.Change` (`""`, `metadata`: the ordered `PublicHash` list of the old file (read up to 1 MiB) is the same, else `candidates`); `output_published.changed` is info for `candidates`, debug for `metadata`; errors never hold line contents. The core sets `id`, `output`, `type`, `lastTickAt`, `lastSuccessAt`; a tick or publish error becomes `state: error` with `error`, never a crash. Events: `output_published`, `provider_tick_failed` (written by the tick, edge-triggered on state and error), `provider_recovered`, `provider_tick_skipped_overrun`, `status_write_failed`, `status_write_recovered`, `server_started`, `server_stopping`, `service_failed`.
- `internal/wgp/server`: `GET /healthz`, `/api/status` (the in-memory status document), `/` (embedded `page.html.tmpl`, dashboard colours, no JS); other paths `404`, other methods `405`.
- `internal/crosstest/wgp_test.go`: fake providers go config → daemon → output → `status.json`, then scd reads the same bytes (`manifest.LoadPrivate`, `candidate.Parse*`, `manifest.BuildCandidates`, `wgpstatus.Read`).
- `providers` needs ≥ 1 entry.
- `internal/wgp/transport` (shared by API providers, names no provider): `New(Config{BaseURL, Mode, Spec, Prepare, RootCAs, API})`, `Client.Do(ctx, Request{Method, Path, Header []Header, Body, Dialed}) (Response, error)`; `Dialed` (optional, Raw mode only; HTTP mode rejects it) is called once per attempt right after the TCP connect, before the TLS handshake, so concurrent requests start in a fixed order (the Proton post-login batch). Per attempt `api.timeoutMs`; 429/503 wait `Retry-After` (seconds or a date, capped at 1 h) else a random `minDelayMs..maxDelayMs`, 408/502 retry at once, at most `api.retry.attempts`; network errors and timeouts are not retried (their text drops the local address, `common/neterr.Stable`). A status ≥ 400 returns the last `Response` and `*StatusError{Status, Code, Message}` (only the JSON `Code`/`Error` fields, never the body, headers, path or request). TLS: uTLS `HelloCustom` + `ApplyPreset(Spec())` per connection, optional `Prepare`, full certificate verification. `HTTP` mode: `net/http` over that dialer, HTTP/1.1, keep-alive, one session cache per Client, no redirects. `Raw` mode: request line and the headers exactly as given (order, case; `Host` and `Content-Length` come from the provider and Content-Length must match the body), one connection per request, the response via `http.ReadResponse` (Content-Length or chunked; `gzip`, `deflate`, `zstd` with an 8 MiB window), then the raw `net.Conn` is closed (TCP FIN, no TLS alert). Response bodies ≤ 32 MiB after decoding. Headers, specs, JSON codecs, constants and base URLs live in the provider packages.
- `provider/warp` (`identification.warp.{userAgent,clientVersion,apiVersion,model,locale,osVersion}` all required; outputs need `candidates` = devices; no `Interactive`): `tunnel: wireguard` → `Kind = wireguard`, `tunnel: masque` → `Kind = masque` (subtree `wireguard` xor `masque`, the other is a config error). State record `{devices[]{id, token, privateKey, masqueKey, profile{clientId,v4,v6,peerKey,endpoint,endpointV4}, lostChecks, registerAttemptAt}}`, one slot per candidate, saved after every change. Per tick and slot: `GET /reg/{id}` (`200`+`enabled` resets `lostChecks`; `404`/1006, `401`/1012, `enabled: false` count; anything else neither); at `deviceLostAfterChecks` the slot is cleared (keeping `registerAttemptAt`) and its line withdrawn; an empty slot saves `registerAttemptAt = now` and then `POST /reg`s (X25519, `regBody`), unless `registerAttemptAt + reRegisterMinIntervalMinutes` is ahead (failed attempts count; a never-tried slot goes at once); no device in any slot → no lines and no error (the output empties), no line while a device exists → tick error; `keys.rotateOnStart` → `PATCH /reg/{id}` once per process after a healthy check (not for a device registered in this process). The profile comes from POST/PATCH answers, and from a GET answer only when its `key` is the current public key. Line: `candidate.WireGuard` (`reserved` = base64 `client_id`, exactly 3 bytes; endpoint from the API, port replaced by `wireguard.port`; DNS/MTU/allowedIPs from the config) → `FormatWireGuard` → `ParseWireGuard`. MASQUE shares the same slot lifecycle; only the key step differs: a device without `masqueKey` (just registered, or its PATCH failed) and `rotateOnStart` get a new P-256 key by `PATCH /reg/{id}` (`secp256r1`, `masque`), after a healthy check or the registration; the current key for a GET answer is then the base64 PKIX. MASQUE lines: `candidate.Masque` (PEM PKIX P-256 `public_key` → `peerkey`, `endpoint.v4` with `masque.port`, addresses, `masque.sni`/`dns`), one per `masque.transports` entry with `priority` = index → `FormatMasque` → `ParseMasque`. WARP error codes are read from `errors[0].code` into `StatusError.Code`. Errors name the device number (`device N: …`), never its id, token or key. Events (`Result.Events`, also with a tick error or cancellation): `device_registered`, `device_register_failed` (`notBefore`; until the next attempt the status error stays the attempt's text, `register: … (next attempt not before T)`, so it changes once per interval), `device_key_rotated` (`keyType`, `reasonCode` = `rotate_on_start|new_device|retry`), `device_check_lost` (`checks`, `after`, `status`, `code`; the error text has no counters), `device_lost`. Tests: `httptest` fake API over `transport.Config.Dial` + `RootCAs`, a test clock, an in-memory `Store` (restart = a new `WARP` on it). `log_test.go` runs the provider through the daemon and checks that no device id, token, key, `client_id`, address or endpoint reaches the log, `status.json` or `/api/status`.
- `provider/proton` (`Kind = wireguard`, `Interactive`; `proton/srp`, `proton/pgp`; outputs need `candidates`; top-level `keys.revokeOldAfterMinutes` is required with an enabled proton provider): `wire.go` is the API layer: `helloSpec` (the official Linux client: 30 ciphers, 13 extensions, encrypt_then_mac as `GenericExtension{Id: 22}`, x448/ffdhe as bare `CurveID`s, key shares X25519MLKEM768 + x25519 with separate keys), `transport.Raw` to `vpn-api.proton.me`, headers from `identification.proton.{appVersion,userAgent,timezone}` in the captured order (`x-pm-timezone` not on ping, refresh, logout; `Content-Length` on every non-GET; `Content-Type` only with a body), bodies by `dumps` (Python `json.dumps` style over `obj`). Tests: `testdata/proton-clienthello.json` and `testdata/proton-requests/*.http` (CRLF, `{{…}}` placeholders, `{{len}}` = body length after substitution). `session.go`/`login.go`: login, the session (`authed`: 401 → one refresh → repeat; 400/422/10013 → `errNeedsLogin`), logout. `tick.go`: `GET /vpn/v2` (`MaxTier`, `MaxConnect`; nothing else read) → `GET /vpn/v1/logicals?SecureCoreFilter=all&WithState=true` (no netzone, no `If-Modified-Since`) → filters (`Status == 1`; free = `Tier 0`, plus = `Tier 1..min(2, MaxTier)`, a tier above `MaxTier` is a tick error; entry = `EntryCountry` for Secure Core, `HostCountry` for Smart Routing, else `ExitCountry`; exit, city, features, `maxLoad`, `maxScore`, never `Score ≥ 1000`), physical = the online one with the smallest `ID`, order `Score, Load, Name`. State record member `keys{gen, rotatedAt, slots[]{seed, gen, serial, expiresAt, refreshAt, server}}` next to `session`, one slot per candidate. Per slot: no key or an older `gen` → a new Ed25519 seed and `POST /vpn/v1/certificate` (`ClientPublicKey, Duration, Features{RandomNAT, SplitTCP, PortForwarding, NetShieldLevel}, Mode: persistent, DeviceName`), else at `min(expiresAt − renewBeforeMinutes, refreshAt)` the same with `Renew: true`; `ClientKeyFingerprint == base64(sha512(x25519 pub))` is checked; WG key `clamp(sha512(seed)[:32])`. `rotateOnStart` adds one to `gen` once per process (when keys exist); a slot that moves to the new `gen` sets `rotatedAt`; `revokeOldAfterMinutes` later `GET /vpn/v1/certificate/all?Mode=persistent&Limit=50` (a full page → the next with `&BeginID=<last serial>`; `Code` not 1000/1001 is an error) and `DELETE /vpn/v1/certificate {"SerialNumber"}` (`Count: 0` = already revoked: counted in `certificates_revoked.alreadyRevoked`, not an error) for names that match `^<prefix><output id>-<gen>-<n>$` exactly with an older `gen` and a serial no slot holds. `DeviceName = <deviceNamePrefix><output id>-<gen>-<n>`. Servers: one per slot, never shared; a server that left the set is replaced at once, a better free one (Score lower by `switchMarginPercent`) only after `switchConfirmChecks` ticks in a row (counters in memory). Line: `10.2.0.2/32` (+ `2a07:b944::2:2/128` on `Features & 16`), `EntryIP:wireguard.port`, `X25519PublicKey`, dns/mtu/allowedips explicit, metadata `server, entry, exit, load, score, expires`, label template (`{flag}` of the exit country, `{city}`, `{name}`). Status: `issued` = slots with a live certificate, `limit = MaxConnect`, `expiresAt` = earliest; `needs_login` returns the error (file kept, nothing rotated). `Logout` revokes every name of the template, drops `keys`, then `DELETE /auth`. Events (`Result.Events`; session events are queued under `mu` and drained by `Tick`): `candidate_server_changed` (`detail` of `gone` from `reject`: `offline|tier|filter|load|score|no_physical`, or `missing`), `certificate_issued` (`mode` = `new|rotation|renew`), `keys_rotated`, `certificates_revoked` (`count`, `alreadyRevoked`; only `alreadyRevoked` = `debug`), `session_refreshed`; a needs_login tick returns `errNeedsLogin` itself, so its text is the same on every tick. Tests: `httptest` fake API (`session_test.go`, `tick_test.go`), test clock, `testdata/x25519.json` (references made with the Edwards → Montgomery map; no `edwards25519` in `go.mod`).
- `provider/static` (no identification, no `candidates`, no state): every `*.conf` of `dir` in `os.ReadDir` (name, `strings.Compare`) order → one `candidate.WireGuard` line `provider=static`. wg-quick format, case-insensitive keys, one `[Interface]`, exactly one `[Peer]`; `# Label` (else the file name without `.conf`), `# Reserved`; `ListenPort Table FwMark SaveConfig Pre/PostUp Pre/PostDown` are warnings, any other unknown key rejects the file. A file is a regular file (Lstat), ≤ `maxFileBytes` (64 KiB), no `0o007` bits. Values are built into a line and checked by `candidate.ParseWireGuard` (the scd rules), then `FormatWireGuard`; missing MTU/AllowedIPs/DNS come from `defaults`. A rejected file: `state: error` + `error` (file and field, never a value), the others are published; no accepted file: tick error. `internal/crosstest/static_test.go`: fixtures → static → `output.Publish` → `manifest.BuildCandidates`.
