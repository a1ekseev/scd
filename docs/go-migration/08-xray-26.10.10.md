# 08. Переход целевой версии Xray: v26.3.27 → v26.10.10

Дополняет `02-scd-xray-api.md` (исследование велось по v26.3.27) в соответствии с решением **D4** (`07-decisions.md`). Где этот файл расходится с 02, действует 08.

Ссылки: `old:<path>:<line>` — дерево Xray-core **v26.3.27** (`d2758a023cd7`, 2026-03-27); `new:<path>:<line>` — дерево **v26.10.10** (`701af60772cd`, 2026-10-10). Между тегами 300 коммитов (`git log v26.3.27..v26.10.10`). Клоны лежат в scratchpad: `xray-core/` и `xray-core-26.10.10/`.

> **TL;DR**
> * **gRPC-контракт scd не изменился.** `app/proxyman/command/command.proto` и `app/router/command/command.proto` между тегами не менялись совсем. Все 9 RPC, их номера полей и семантика ошибок те же; проверено живым прогоном против собранного Xray 26.10.10 (раздел 3).
> * **Номера полей во всех используемых сообщениях те же** (StreamConfig, TransportConfig, websocket, reality, VLESS, SOCKS, ReceiverConfig, RoutingRule, ListRuleItem).
> * **Главное изменение — TLS `allow_insecure` (поле 1) удалён из proto и из рантайма** (`InsecureSkipVerify` больше не выставляется). Go-код `tls.Config{AllowInsecure: …}` **не компилируется**. Кроме того, TLS-клиент по умолчанию использует **встроенный набор корневых CA** (Mozilla), а не системный (`use_system_ca=23`).
> * Оба бага TS-кодера (ws `protocol_name` в поле 1 и fingerprint в поле 10) **на v26.10.10 по-прежнему воспроизводятся**. К ним добавился третий «тихий» случай: `allow_insecure` (поле 1) теперь тоже неизвестное поле.
> * ⚠️ **v26.10.10 на GitHub — Pre-release.** Последний стабильный («Latest») релиз — по-прежнему v26.3.27. Go-тега `v1.261010.0` **нет**. Есть только pseudo-version **`v1.260327.1-0.20261010092107-701af60772cd`**. Docker-образ `ghcr.io/xtls/xray-core:26.10.10` существует (= тег `pre-release`; `latest` = 26.3.27).
> * xray-core v26.10.10 требует `go 1.27`, поэтому Go 1.27.2 подходит. Размер бинаря с нативными пакетами: **22.5 МБ** (было 18.6), +11.7 МБ к «голому» gRPC.

### 2.2. TLS: `allowInsecure` и корневые CA

* v26.3.27: `InsecureSkipVerify: c.AllowInsecure` (`old:transport/internet/tls/config.go:384`). Через protobuf флаг работал, `infra/conf` после 2026-06-01 его отвергал (`old:infra/conf/transport_internet.go:709-716`).
* v26.10.10: поле удалено из proto и из `GetTLSConfig` (`new:transport/internet/tls/config.go:368-405`). `InsecureSkipVerify=true` теперь ставится только при `verify_peer_cert_by_name` или `pinned_peer_cert_sha256` (`:397-405`), и тогда сертификат проверяет `verifyPeerCert`. JSON с `"allowInsecure": true` → `PrintRemovedFeatureError` (`new:infra/conf/transport_security.go:362-363`). Байт `08 01` от старого клиента Go-protobuf сохраняет как unknown field, и он **молча игнорируется**.
* Корневые CA: раньше — системный пул (`old:transport/internet/tls/config_other.go:36-43`, `x509.SystemCertPool`). Теперь `loadCA(c.UseSystemCa)` (`new:…/config_other.go:18-21`, `new:…/config.go:583-617`). По умолчанию (`use_system_ca=false`) используется **встроенный bundle `golang.org/x/crypto/x509roots/fallback`**. Корпоративные или частные CA из ОС контейнера больше не доверены, если не выставить `use_system_ca=true`.
* Следствие для scd: подписки с `allowInsecure=1` (self-signed серверы) на v26.10.10 **перестают работать** независимо от реализации scd. TS-scd просто молча шлёт мёртвое поле. В Go `tls.Config{AllowInsecure: …}` даёт compile error (проверено: `unknown field AllowInsecure in struct literal`).

Все ошибки приходят как `codes.Unknown` с текстом `<package>: <msg>`, как и раньше.

Изменения реализации `Router` (`598bde74`), которые для scd **не меняют наблюдаемое поведение**:
* `ReloadRules` теперь собирает новый список и публикует его атомарно (`atomic.Pointer`) — `new:router.go:89-151` против `old:router.go:124-211`. В старой версии при ошибке в append-режиме новые правила откатывались (`closeNewWebhooks`), а в replace-режиме (`shouldAppend=false`) при ошибке **оставалось очищенное состояние**. Теперь при любой ошибке состояние не меняется. scd всегда шлёт одно правило с `shouldAppend=true`, поэтому разницы нет.
* `ListRule` больше не берёт mutex (`new:router.go:183`). `Init` теперь вызывает `ReloadRules(config,false)` (`new:router.go:43-55`).
* `RemoveRule("")` проверяется до взятия lock’а. Текст ошибки тот же.

Не менялось, но важно для Go-порта (уточнение к 02 §2.2):
* **Порядок `ListOutbounds`/`ListInbounds` недетерминирован** в обеих версиях: сначала untagged, затем итерация по Go-map (`new:app/proxyman/outbound/outbound.go:149-161`, `new:app/proxyman/inbound/inbound.go:93-105`). В прогоне порядок различался между запусками. Fake-сервер и тесты не должны полагаться на порядок; rollback должен восстанавливать удалённое по сохранённому списку, а не по порядку ответа.

Новое и потенциально опасное для scd:
* **Lua routing script** (`8855145e`): если в статическом конфиге задан `routing.script`, то `PickRoute` полностью уходит в Lua (`new:app/router/router.go:57-60`, `new:app/router/script.go:54-76`). Правила, добавленные через `AddRule`, при этом хранятся и видны в `ListRule`, но **не применяются**. scd этого не увидит. Рекомендация: документировать как неподдерживаемую конфигурацию.

## 6. Баги TS-кодера на v26.10.10

Байты TS-билдеров (`scratchpad/tsgen/out.json`) декодированы типами v26.10.10 и отправлены в живой Xray 26.10.10:

```
tcpTls:  EFFECTIVE tls: sni="example.com" fingerprint="" unknown=080052066368726f6d65
                                                           ^^^^ allow_insecure=false (поле 1) — теперь тоже unknown
                                                               ^^^^^^^^^^^^^^^^ "chrome" в поле 10
wsTls:   transport[0].protocol_name=""  unknown=0a09776562736f636b6574    ("websocket" в поле 1)
         EFFECTIVE ws: path="" host="" header=map[]
         EFFECTIVE tls: sni="cdn.example.com" fingerprint="" unknown=520766697265666f78   ("firefox" в поле 10)
reality: OK
```
Список outbound’ов после `AddOutbound` нативными типами: `go-ws-tls tls fp="firefox" ws path="/ws" host="ws.example.com"`, т.е. корректно.

1. **ws `protocol_name`**: поле 1 вместо 3 — **баг сохраняется** (`TransportConfig` не менялся). Фактический эффект в обеих версиях: path → `/` (`GetNormalizedPath`). `Host` — **не пустой**: dialer подставляет `tlsSettings.serverName`, затем адрес (`old:transport/internet/websocket/dialer.go:131-137`, `new:…:136-141`). Это уточнение к 02 §1.4: Host теряется, только если ws-host отличается от SNI.
2. **TLS fingerprint**: поле 10 вместо 11 — **баг сохраняется**. Уточнение к 02: пустой fingerprint — это не «без uTLS», а `HelloChrome_Auto` (`GetFingerprint("")`, `old:transport/internet/tls/tls.go:180-183`, `new:…:221-224`; используется в `new:transport/internet/tcp/dialer.go:73`). Значит, подписочные `firefox/safari/…` подменяются на Chrome. Имена пресетов (`chrome, firefox, safari, ios, android, edge, 360, qq, random, randomized, …`) не менялись (`new:tls.go:237-250`).
3. **Новое**: `allow_insecure` (поле 1) — неизвестное поле, `InsecureSkipVerify` не включается (раздел 2.2).

## 8. Риски и решения для владельца

1. **Pre-release как целевая версия.** v26.10.10 и все релизы после v26.3.27 — Pre-release. Go-тега нет, `@latest` указывает на 26.3.27, и Dependabot/Renovate не предложат pseudo-version. Сам Xray Go API стабильности не обещает: в окне 26.3→26.10 удалены `router.GeoIP/Domain/CIDR`, `tls.Config.AllowInsecure`, `ProxyConfig`, перенумерован `QuicParams`. Митигировать так: pin по коммиту, `go mod verify` в CI, изоляция в `internal/scd/xrayapi` (как в 02 §5), обновлять go.mod и compose вместе (D4).
2. **allowInsecure (нужно решение).** Варианты для Go-версии:
   a) молча игнорировать, как де-факто делает TS на 26.10.10;
   b) **рекомендуется:** при `allowInsecure=1` логировать warning (`allowInsecure is not supported by Xray ≥ v26.6.22; outbound will verify certificates`), в gRPC не передавать, в `jsonOutbound`/`manifestHash` оставить для стабильности хэша;
   c) отбрасывать такие entries на normalize, как `infra/conf`.
   Отдельно стоит рассмотреть поддержку `pcs`/`vcn` (`pinned_peer_cert_sha256=22`, `verify_peer_cert_by_name=17`) из URI подписки — это штатная замена от Xray, но это новая функциональность.
3. **Корневые CA.** С v26.10.10 TLS-outbound’ы доверяют только встроенному Mozilla-bundle. Если какой-то сервер подписки подписан частным CA, установленным в образ, — сломается. Опция `use_system_ca` в scd пока не нужна. Достаточно зафиксировать это в README.
4. **SOCKS UDP ASSOCIATE** (`new:proxy/socks/protocol.go:193-215`): UDP-relay теперь на **эфемерном** порту, адрес — `conn.LocalAddr()` или `ServerConfig.address=3`. Для туннелей scd (`socks` inbound на фиксированном порту, `udp_enabled=true`) UDP-клиенты **снаружи Docker** (через опубликованный порт) получат недоступный ip:port. TCP-путь и HTTP-проверки мониторинга scd не затронуты. Если UDP через туннели нужен вне контейнера — требуется `network_mode: host` или отдельное решение. Зафиксировать как известное ограничение.
5. **Lua `routing.script`** в статическом конфиге отключает все правила, включая правила scd, а scd этого не видит. Документировать как неподдерживаемую конфигурацию. Опционально — warning в status, если `TestRoute` показывает несоответствие.
6. **Размер/граф зависимостей** вырос (+3.9 МБ, Lua, bundle CA). Решение D5 (нативные пакеты) это не отменяет, но запасной вариант «вендорить .proto и генерировать» стал выгоднее на ~12 МБ.
7. **Неизменённые баги TS.** Если до полного перехода на Go продовый TS-scd будет работать против Xray 26.10.10, к двум известным багам добавится тихая потеря `allowInsecure`. Для TS-ветки это не регрессия к 26.3.27 только в части ws/fp. Для allowInsecure-подписок это регрессия, вызванная самим Xray.
